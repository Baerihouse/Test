# 현장별 PDF 검토 → 3D 모델 저장 (제품 0.3.0)

- 사용자 요청: 6개 메뉴(현장목록/도면관리/도면검토/마감재관리/3D모델/설정), 현장명·건물타입·층 관리, PDF 우선 등록, 부족한 치수와 벽/개구부/창호 수정, 미확정 표시, 현장/층별 모델 저장과 모아보기.
- 변경 전: 샘플 대시보드와 고정 84A 초안. 새 PDF를 받아 모델을 만드는 사용자 흐름 없음.
- 변경 후: 실제 빈 현장 목록 → 현장/층 등록 → 여러 PDF의 종류/층 지정 및 원본 저장 → PDF 페이지 표시 → 두 점/실제치수로 축척 지정 → 두 점으로 벽 추가 및 수치 수정 → 벽별 문/창 개구부 입력 → 생성 버튼으로 검토 스냅샷 저장 → 단일 층/현장 내 여러 층 3D 모아보기. 미정값은 참고 높이와 주황색으로 구분.
- 자동 인식: 이번 버전은 **사용자 검토/추적 방식**. PDF를 넣었다는 이유로 벽이 자동 인식되었다고 표시하지 않음. DWG/DWF는 명확하게 미지원 안내.
- 기존 84A: 원래 URL을 보존하고 설정 화면에서 참고 모델 링크 제공. 기존 localStorage 자재도 유지. 새 현장 데이터에 84A를 자동 복제하지 않음.

## 저장·ERD 사전 검토

- 현재 ERD는 원격 SQL 테이블 0개. 원격 Supabase/운영 DB·RLS·migration은 변경하지 않음. 실제 기존 코드가 브라우저 저장 제품이므로 동일 로컬 범위 확장.
- 사용자별 IndexedDB version1: `workspace`(사용자ID → 버전1 aggregate), `files`(사용자ID:도면ID → PDF Blob). 현장 아래 층/도면/벽/개구부/모델 이력과 자재를 중첩 저장. 서버DB의 FK처럼 보이는 실선 SQL ERD를 만들지 않으며 구조는 별도 로컬 관계 문서에 기록.
- 참조 대상: drawing은 같은 층, opening은 같은 벽, material은 같은 현장에만 연결. 스냅샷은 생성 당시 geometry와 층 높이를 복제해 과거 결과가 편집으로 바뀌지 않음.
- 식별: UUID. 중복ID/층명/도면 참조/유효범위 검증. 사용자간 DB키 분리. null은 미정 높이·두께·위치 기준을 뜻함.
- 저장: PDF Blob과 메타데이터는 한 IndexedDB transaction. commit 완료 후만 성공 표시. aggregate revision 충돌은 덮어쓰지 않고 재로드 안내. PDF 열기·형식 검증 실패는 등록하지 않으며, 특정 페이지의 표시 실패는 미리보기에서 별도 오류로 안내한다(모든 페이지를 미리 렌더 검증하는 것은 아님).
- 삭제: 확인 후 층의 도면/검토/스냅샷 및 파일 Blob을 함께 제거. 샘플/기존 localStorage 데이터는 삭제하지 않음.
- 보관 한계: 현재 브라우저/장치별 로컬. 로그인은 기존 데모 인증이며 타 기기 동기화/조직 공유·운영 보안은 아님. JSON 내보내기는 검토·모델 메타데이터이며 PDF 원본은 별도 보관하도록 표시.
- 롤백: 신규 workspace route/layout 연결을 제거하면 기존 화면 복구 가능. 새 IndexedDB는 지우지 않고 보존. 원본 PDF와 기존 사용자 수정 보존.

## 좌표·3D 계약

- PDF.js가 페이지를 렌더. 정규화 페이지 좌표(0~1)를 기록하고 페이지의 너비/높이 비율과 두 기준점의 mm 길이로 축척 확정. 도면 페이지가 바뀌면 calibration도 구분.
- 벽은 mm 좌표·높이/두께 nullable, 근거 문구, 확인 여부. 재보정 시 같은 페이지에서 추적한 벽만 재계산하고 검토 필요로 돌림.
- 문/창은 벽 시작점에서 거리·폭·높이·하단 높이로 연결. 벽 범위 밖·중첩 개구부는 저장 거부. 형상은 개구부를 제외한 벽 조각으로 생성. 미정 벽은 설정된 **참고** 높이/두께를 사용하며 확인 완료로 간주하지 않음.
- 모델 스냅샷에 PDF 출처 ID/페이지와 확인 상태 유지. 검토 수정 시 기존 스냅샷은 보존하고 '재생성 필요' 표시.
- 현장 모아보기는 사용자 입력 층 SL 및 동일 XY 원점 기준으로 배치. 여러 도면 원점이 다르면 자동 정합했다고 표시하지 않음.

## 검증

- 현장/층 분리·파일 타입/MIME/크기/매직·잘못된 PDF·축척·개구부 범위/중첩·미정 상태·스냅샷 고정·동시쓰기 충돌·재시작 저장을 테스트.
- 실제 첨부 PDF 등록/페이지 전환/보정/벽 추적/문창 수정/3D생성/층 모아보기/새로고침/실패 시 기존데이터 유지/메뉴·모바일·WebGL 오류 확인.
- 자동 검사 5종 및 소스/실행복사본 해시 대조. C: 기존 실행본에서 검증하고 E: 소스 보존.

## 실행 결과

- 구현 완료: 6개 메뉴, 현장/타입/층 등록, PDF 다중 등록·분류·미리보기·원본 내려받기, 페이지별 보정, 벽 중심선 추적·수치 수정·개구부/창호 추가·수정/삭제, 마감재 리스트/벽 연결, 생성 모델 이력·삭제, 현장 내 최신 층 모델 모아보기, 실제 설정.
- 자동 검사: format:check / typecheck / lint / test / build. 테스트 6개 파일 32건 통과. 기존 React Router 미래 옵션과 PDF/Three.js 동적 chunk 크기 경고가 있으나 빌드 성공. 경고 한도를 조작하지 않음.
- 실제 PDF 기능 검증: 첨부 84A 확장형 PDF를 신규 현장에 등록하고 보정/벽/창호를 입력해 3D 생성 및 재열기. 이는 기능 검증용 임의 중심선이며 자동 도면 인식 정확도나 실제 건물 형상 전체의 검증이 아님.
- 생성 이력: 검토 수정 시 이전 모델 유지/재생성 필요 알림, 재생성 후 이력 2개 보관, 다른 층의 미확정 벽도 주황색으로 모아보기. 2층 GL+3,550 / 3층 GL+6,350 배치 확인.
- 저장: 새로고침 후 PDF/벽/개구부/모델 유지. 다른 현장 선택 시 PDF 목록 분리. 같은 브라우저에서 관리자 로그아웃 후 매니저 로그인하면 관리자 자료가 보이지 않음 확인.
- 실패 처리: DWG 거부, 위조 PDF 거부, 유효+무효 PDF 다중 등록의 부분 저장 방지. IndexedDB put 오류를 강제해 메타 revision/기존 PDF 개수 유지 확인. 두 탭의 동시 편집에서 오래된 revision 쓰기를 거부하고 최신 이름 보존.
- 삭제: 층 삭제 취소 시 데이터 그대로, 확인 후 선택 층의 PDF Blob과 검토/모델 함께 삭제. 다른 층과 파일은 유지.
- PDF 페이지: 2페이지 PDF 생성해 표시·페이지 전환 확인, 1페이지 보정이 2페이지로 유출되지 않음 확인. 원본 내려받기의 SHA-256이 등록 파일과 일치.
- UI: 1920×1080 / 1600×1000 / 1366×768 / 390×844 / 412×915 / 844×390에서 가로 넘침 확인. 긴 현장명, 숫자 범위/이름 누락/제품명 길이 오류 문구 확인. 주요 시나리오 콘솔 오류/페이지 예외/4xx·5xx 0건.
- 테스트는 격리된 브라우저 컨텍스트에서 실행해 실제 사용자 현장 데이터를 만들거나 삭제하지 않음. 기존84A 자료와 원본 PDF 파일은 그대로 보존.
- 위키: 기존 색인 확인, 제품별 기존 기록 없음. 이번 작업의 원천은 이 설계/검증 기록과 실제 코드로 유지.

## 남은 범위

- PDF 자동 벽 인식, DWG/DWF, 도면 회전·여러 도면의 자동 정합, 실제 창호 제품/마감층/슬래브 생성, 시공 순서 재생은 후속.
- 다른 기기/조직 공유·운영 인증·클라우드 저장, JSON 복원 UI, 실제 휴대폰 GPU/터치 및 대용량 부하 검증은 미실행.
- 현재 JSON 백업은 메타데이터만 포함하고 PDF는 별도 보관해야 함. 원본 E:에서 설치/실행은 기존 pnpm 링크 오류 때문에 C: 동일 소스로 검증.
